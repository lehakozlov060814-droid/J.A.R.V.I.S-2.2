# Nexora 1.1.0 — Visual Experience & Living Mascot: проверка

Визуальный проход поверх Sol commit `0c0f8e6`. Бэкенд (`main.py`, `personal.py`,
`miniapp.py`, `live.py`, `telegram_context.py`) совпадает с ним побайтно. API, SQLite,
авторизация, модели, тарифы, квоты и production не менялись.

## Выполнено

- CPython 3.12.14: `python -m unittest discover -s tests -q` — **428 тестов,
  427 прошли, 1 пропущен (существующий платный live-тест), ошибок нет**.
- Node 24.22.1: `node --check web/app.js`; `node --test tests/frontend.test.cjs` —
  **19 прошли, ошибок нет**. Для этого набора достаточно Node 18+; runtime не требует Node.
- Итого: **447 тестов, 446 прошли, 1 пропущен**.
- Старый release-тест требовал неизменности дизайна из-за прошлого задания. Он намеренно
  заменён на проверку пяти неизменённых backend-файлов Sol по фиксированным SHA-256.
- JS-набор исполняет настоящий `web/app.js` с минимальными DOM/API doubles: onboarding,
  авторизационный заголовок, escaping имени, переключение темы/safe areas, выбор модели,
  Pro restriction, настройки, группы/Back, память/подтверждение, сетевые ошибки,
  блокировка повторного клика, обновление квот, reduced motion и visibility pause.
- Проверены три различных совместимых SVG-контура (по восемь кубических сегментов),
  замкнутый цикл `d`/18 секунд/spline и вызовы SVG timeline hooks. Это **структурная
  проверка морфинга**, не визуальное подтверждение его плавности.
- Контраст вторичного текста на верхнем цвете градиента и карточках рассчитан:
  минимум 4.5:1 в обеих темах. Это не полный accessibility-аудит.

## Ограничения

- Browser-тесты не выполнены. Локальный Chromium завершился с `socket() failed:
  Operation not permitted`; открытие локального fixture-сервера облачным браузером
  отклонено автоматической проверкой доступа из-за риска передачи локальных данных
  и тестовой авторизации внешнему сервису. Обход не предпринимался.
- Мобильная отрисовка 320/360/390/430 px, отсутствие переполнения, визуальная плавность
  морфинга и работа реального WebView iOS/Android **не подтверждены**. Ручной чек-лист
  в `DEPLOY.md`; не считать выпуск визуально принятой production-сборкой до этой проверки.
- JS API doubles не доказывают real Telegram/OpenRouter integration. В Python-наборе
  есть настоящие локальные HTTP/SSE/SQLite-проверки и моки внешних сервисов (см. ниже).
- Реальных Telegram/OpenRouter, платной генерации, GitHub и BotHost не было.

## Файлы визуального прохода

`web/index.html`, `web/app.js`, `web/style.css`, `tests/frontend.test.cjs`,

# Сохранённый отчёт Sol — Telegram, streaming и память

Этот проход продолжает приложенный `Nexora-1.1.0-source.tar(1).gz` в отдельной рабочей
копии. Исходная основа сохранена локальным commit `8655781`; заново проект не создавался.
BotHost, действующая 1.0.10, production SQLite и GitHub не открывались и не изменялись.

## Результат автоматической проверки

CPython **3.12.14** в текущем окружении:

```sh
python -m py_compile main.py personal.py miniapp.py live.py telegram_context.py
python -m unittest discover -s tests -q
node --check web/app.js
```

**428 тестов: 427 прошли, 1 пропущен, 0 ошибок.** Пропущен существующий платный opt-in
live-тест характера. Все 389 тестов основы сохранены. Добавлены 39 тестов в
`tests/test_experience1100.py`. В двух старых packaging-тестах перечень локальных модулей
обновлён с учётом `live.py` и `telegram_context.py`; проверки стандартной библиотеки сохранены.
Новый тест проверяет импорты всех пяти runtime-модулей и синтаксис Python 3.11 через AST.
**Интерпретатора Python 3.11 здесь нет; фактический запуск на нём повторить перед установкой.**

## Что подтверждено кодом и тестами

- До изменений: почти всякий текстовый reply к Nexora сразу получал direct, даже если
  обращался к людям; HTTP-клиент целиком читал JSON, SSE не было; память выбиралась по
  буквальному пересечению слов из последних 50 подтверждённых записей.
- Локальные правила теперь исключают команды чужих ботов, ролевые команды, чужие mentions,
  явные обращения к ребятам, просьбы не отвечать и очевидное обсуждение Nexora.
  Неоднозначный reply получает существующий address-gate, с теми же лимитами 20/сутки
  и интервалом не менее 60 секунд. Без уверенного решения бот молчит.
- Gate получает до 6 коротких сообщений той же форумной темы и Telegram metadata.
  Основной ответ видит автора/reply-адресата/тему/причину активации, отдельные speaker labels.
- Настоящий SSE запрашивается `stream=true`, usage включён. Комментарии SSE, CRLF,
  многострочные data, UTF-8, `[DONE]`, finish_reason, usage и mid-stream errors обрабатываются.
  Служебные поля, JSON памяти и reasoning не показываются в превью. Объём/время ограничены.
- Реальный **loopback HTTP/SSE** тест доказывает доставку первого фрагмента до окончания
  серверной генерации: сервер ждёт подтверждения получения первого фрагмента клиентом.
- Ещё 4 настоящих loopback HTTP-теста: обычный JSON вместо SSE (один POST), HTTP 429 с
  Retry-After и максимумом 3 попытки, длинный Retry-After без повторного запроса,
  ошибка внутри начавшегося SSE без повтора с сохранением известной стоимости.
  Это локальные TCP-запросы, **не реальные запросы в OpenRouter**.
- Telegram typing/draft/edit/cleanup, native Stop вне блокировки чата, форумный topic,
  fallback старого Bot API и косметический 429 проверены **моками**. Превью не чаще раза
  в 4 секунды, до 8 обновлений; общий предел косметики 20/сек и 10 сообщений/мин на чат.
  Быстрые ответы не порождают ожидающего сообщения. Финальный ответ сохраняется обычным
  sendMessage/editMessageText, длинный разбивается прежним способом.
- После начавшегося потока нет повторной генерации; известный HTTP-отказ возвращает резерв
  и персональный слот. При неопределённом исходе остаётся оценочный денежный резерв и
  временный quota hold только данного запроса. generation ID сохраняется для прежней
  ограниченной read-only сверки расходов. Отмена не гарантирует отмены оплаты провайдером.
- Параллельные участники, повторные updates, скользящие персональные квоты, ограничения
  бюджета, права Pro, HMAC initData, server-side admin checks и совместимость старой SQLite
  проходят прежние и новые регрессии. Нового общего тарифного счётчика группы нет.
- Подтверждённая память выбирается из ограниченного пула до 300 записей по теме, участнику
  и актуальности, до 8 записей/2800 знаков. Короткий follow-up может использовать тему reply.
  Источники и даты передаются отдельно; pending/expired/superseded не считаются фактами.
- Пересылки не направляются в платный отбор кандидатов. Добавлены проверки слухов, шуток,
  ролевых команд и чужих личных характеристик; preference/nickname требуют ID автора.
  Основной механизм пакетного анализа, проверки цитат и подтверждения администратором сохранён.
- Личные заметки выбираются по теме только в ЛС (до 8/2000 знаков); явный вопрос о памяти
  даёт ограниченный список. В группы заметки не передаются, в том числе с cross_chat=true.
  Повторное сохранение с отличием регистра/пробелов идемпотентно даже при заполненном лимите.
- Разные числа и отрицания не схлопываются в дедупликации контекста. Обновление группового
  факта по-прежнему сначала кандидат с supersedes; администратор подтверждает замену.
- Генерация/редактирование изображений, правильные исходные байты, reply-цепочки,
  compound intents, поиск, приватность и финансовая защита покрыты прежними тестами.
  Изображения не переведены на SSE, image_model не менялась.

## Что не проверено и ограничения

- Реальные Telegram, OpenRouter, provider cancellation и визуальное качество редактирования
  фотографий в этом проходе не проверялись. Платные вызовы не выполнялись, токены не читались.
- Поведение конкретной модели в живом русском разговоре и качество шуток не доказаны
  моками. Фильтр локальных правил намеренно осторожный; нестандартные формы могут пропускаться.
- Ранжирование памяти лексическое, с простыми русскими префиксами, без embedding-вызовов;
  это не полное семантическое понимание. Очень старые записи вне пула 300 не попадают в ответ.
- При разрыве без достоверной стоимости оценка может оставаться консервативной до сверки;
  точную фактическую стоимость нельзя обещать, если провайдер её не вернул.
- В приватном чате sendMessageDraft используется согласно официальной документации;
  для групп он не вызывается. Старый API может перейти на обычное сообщение. Частичное
  сообщение исчезает/удаляется при ошибке; если удаление недоступно, есть попытка заменить
  его коротким сообщением о неудаче. При полном отказе Telegram cleanup не гарантируется.
- Изменений дизайна Mini App нет: SHA-256 всех трёх web-файлов совпадают с приложенной
  основой. Новая визуальная проверка в браузере не выполнялась по суженному заданию.
- Экономия денег не измерялась и не заявляется. Для обычного ответа остаётся один основной
  вызов; streaming/статусы не требуют дополнительных LLM. Неочевидный reply может вызвать
  существующий ограниченный фоновый gate; шутки/пересылки меньше попадают в память локально.
