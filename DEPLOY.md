# Nexora 1.1.0: установка и откат

Рабочая 1.0.10 не изменена. Новый код готовится в отдельной локальной ветке
`release/1.1.0`. Удалённый репозиторий недоступен (GitHub 404); это не доказывает,
что репозитория нет. Изменения туда не загружены. Никакие действия в BotHost,
BotFather, переменных окружения или активной SQLite при разработке не выполнялись.

## Состав выпуска

Для работы нужны вместе **восемь файлов**, с сохранением путей:

- `main.py` — существующий бот с интеграцией профилей.
- `live.py`, `telegram_context.py` — SSE/статусы и Telegram-контекст (обязательны).
- `personal.py` — профили, центральные правила квот и HMAC.
- `miniapp.py` — HTTP-сервер и API в том же asyncio-процессе.
- `web/index.html`, `web/app.js`, `web/style.css` — Mini App.

Python 3.11, только стандартная библиотека. `requirements.txt` не требуется.
Node/npm для запуска и сборки не нужны. Dockerfile не добавлен.
Остальные файлы — документация, тесты и альтернативная конфигурация VPS.
Сначала загрузить всё в отдельную ветку GitHub, не main с автодеплоем.
Не менять J.A.R.V.I.S. и другие боты, даже если источник Nexora размещён в общем репозитории.

## Дополнение Complete Experience

В проходе Sol сервер и GitHub не открывались. В текущем визуальном проходе изменены
только web-файлы, тесты и документация; backend Sol сохранён без изменений.
Новые обязательные переменные окружения не нужны. `NEXORA_STREAMING=0` — необязательный
серверный fallback, если конкретный прокси не пропускает SSE; по умолчанию включён реальный
поток. Не меняет модели, токены и бюджеты. Отдельного веб-сервиса для Telegram streaming
не требуется: бот сам получает SSE от OpenRouter через исходящий HTTPS.

Установить всю папку из архива, а не только main.py: runtime теперь содержит 5 Python-
модулей и 3 web-файла. Точка входа прежняя. SQLite-миграция из подготовленной основы
сохранена; дополнительной схемы в этом проходе нет. Для обновления с 1.0.10 сначала
согласованно остановить старый процесс, сделать SQLite backup с WAL (см. ниже), затем
обновить полную папку. **Здесь никакие действия над production не выполнялись.**

Отдельную тестовую копию запускать только с другим тестовым Telegram-токеном и отдельным
`NEXORA_DB_PATH`. Без токена и оплаты доступна проверка `python -m unittest discover -s tests -q`.
Не запускать два poller-процесса на одном токене. При откате вернуть старый код и backup,
сделанный перед обновлением; данные, появившиеся после backup, сначала сохранить отдельно.
Не удалять файлы действующей БД и не копировать только .db при активном WAL.

Проверить вручную перед production:

1. В группе ответить на сообщение Nexora: «Ребята, вы это видели?», затем отправить
   команду Iris; Nexora молчит. Явное «Нексора, объясни…» получает ответ.
2. В ЛС попросить длинное объяснение: настоящий текст появляется в черновике, Stop
   останавливает текущий ответ. В группе появляется одно редактируемое сообщение.
3. Переслать несколько шуток и написать ясное решение: кандидат требует проверки;
   личная заметка доступна в ЛС, отсутствует в ответе группы даже с cross_chat.
4. Повторить существующий image-edit тест с reply на фото: исходные байты должны
   сохраняться; транспорт изображений не переведён на SSE.

HTTP 429 интерфейсного статуса не повторяет генерацию. При неизвестном результате SSE
сохраняется оценка стоимости до сверки; отмена не обещает нулевых расходов у провайдера.

## Проверка до установки

В отдельной рабочей папке:

```sh
python3.11 -m unittest discover -s tests -q
python3.11 -m py_compile main.py personal.py miniapp.py live.py telegram_context.py
```

Неоплачиваемая локальная проверка панели с тестовым профилем:

```sh
python3.11 tests/preview.py
```

Открыть `http://127.0.0.1:8765` на том же компьютере. Это **явно маркированный fixture-сервер**,
временная БД, тестовые подписи Telegram, мокированные каталог и права. Он не запускает
polling, не обращается к платному API и не нужен в BotHost. В production нет маршрута
`preview-auth.js` и нет обхода проверки подписи. Не публиковать тестовый сервер наружу.

Настоящая панель без подписанного Telegram initData показывает просьбу открыть её из бота.
Это ожидаемо. Внешний браузер сам по себе не авторизует пользователя.

## Проверка нового визуального интерфейса

```sh
node --check web/app.js
node --test tests/frontend.test.cjs
```

Node 18+ нужен только для этих тестов. Никаких npm-зависимостей и сборки frontend нет.
После запуска локального `tests/preview.py` проверить в браузере на том же компьютере:

1. Ширины 320, 360, 390 и 430 px: Главная, Группы, конкретная группа, Настройки,
   диалог моделей, длинное имя/название группы, открытая клавиатура. Не должно быть
   горизонтальной прокрутки, перекрытия нижней навигацией и обрезанных переключателей.
2. Тёмная и светлая тема: fixture задаёт dark. Для light в локальной тестовой копии `tests/preview.py`
   замени `colorScheme:"dark"` на `colorScheme:"light"` и перезапусти только fixture.
   В настоящем Telegram тема меняется его штатным событием, без изменения кода.
3. Наблюдать маскот 18 секунд: меняется сам контур, сохраняется узнаваемая форма,
   движение без скачка на замыкании. Касание даёт короткую реакцию. Reduced motion
   останавливает всё движение; скрытая вкладка ставит анимации на паузу.
4. Выбрать Flash, нажать заблокированную Pro, сохранить имя и предпочтения, изменить
   разрешение памяти, добавить/удалить заметку, открыть группу и изменить инициативность.
   Обновить страницу: значения сохраняются в fixture-БД до остановки fixture-процесса.
5. Включить offline в DevTools и нажать «Обновить»: видна понятная ошибка, профиль
   не заменяется фиктивными данными. Вернуть сеть и повторить. Проверить кнопку «Назад».

**Эти визуальные проверки в текущем окружении не выполнены: запуск/доступ браузера
был заблокирован.** Перед production повторить их в реальном Telegram на iOS/Android,
особенно safe areas, клавиатуру, reduced motion и системную кнопку Back.

Для теста нового дизайна без production достаточно fixture выше. Если уже установлена
именно backend-сборка Sol 1.1.0, визуальное обновление требует только трёх `web/*` файлов;
обновлять их согласованно, затем полностью закрыть и заново открыть Mini App. Новые env
и миграция не нужны. Если работающий бот всё ещё 1.0.10, это **не** обновление только веба:
использовать полную процедуру 1.0.10 → 1.1.0 ниже с backup и проверкой HTTPS.

Для отката только дизайна вернуть прежние три `web/*` файла из архива Sol, не менять БД.
Для отката всей версии с 1.1.0 на 1.0.10 — раздел «Откат» ниже.

## Переменные окружения

Существующие секреты не изменяются:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Существующий токен Nexora, предоставляемый BotHost. **Не создавать вторую одноимённую переменную.** |
| `OPENROUTER_API_KEY` | Существующий ключ OpenRouter |
| `BOT_OWNER_ID` | Необязательный числовой Telegram ID владельца: скрытая `/diag`, временная выдача Pro |

Новые настройки без секретов:

| Переменная | Значение |
|---|---|
| `MINIAPP_URL` | Реальный HTTPS origin панели, например `https://ваш-домен`; без пути, query и завершающего `/`. Нужен для кнопки Mini App в `/start` и проверки Origin. |
| `PORT` | Порт, заданный BotHost; код читает его автоматически. По умолчанию `8000`. Порт в панели и процессе должны совпадать. |
| `WEB_BIND` | По умолчанию `0.0.0.0` для прокси BotHost; на отдельном VPS с локальным Caddy можно `127.0.0.1`. |
| `NEXORA_DB_PATH` | Необязательно. Если не задана — прежняя `/app/data/nexora/nexora.db` (или прежний локальный fallback). Не менять на рабочем обновлении без необходимости. Для отдельного теста — отдельный путь. |
| `NEXORA_BACKGROUND_MODEL` | Необязательный серверный override служебной модели. Без него сохраняются существующие настройки фоновой модели из БД. |
| `NEXORA_SYSTEM_MODEL` | Отдельная модель инициативы; по умолчанию прежняя `google/gemini-2.5-flash`. |
| `NEXORA_VISION_MODEL` | Специализированный анализ фото при текстовой основной модели; по умолчанию `google/gemini-2.5-flash`. |

Не создавать `.env` в публичном GitHub. `main.py` не читает .env автоматически.
На BotHost все значения вводятся в его интерфейсе переменных. На VPS можно использовать
защищённый `/etc/nexora.env` для примера systemd; доступ только владельцу процесса.

## Публикация HTTPS на BotHost

Согласно документации BotHost, опция домена настраивает HTTPS reverse proxy на внутренний
порт процесса. Наличие такого домена для конкретного текущего проекта/тарифа и доступность
ноды должны быть проверены в панели: не предполагается, что URL уже есть.

1. Сначала закончить подготовку ветки и сохранить резервную копию данных.
2. В согласованное окно обновления остановить **только Nexora 1.0.10**. Убедиться, что
   остановка действительно выполнена; при рассинхроне панели обратиться в поддержку.
3. Загрузить/подключить ветку с **всеми восемью runtime-файлами**. Точка входа — `main.py`,
   запуск — прежний Python 3.11 (`python main.py` в настроенном окружении).
4. Настроить домен/поддомен и внутренний порт `8000` в этом проекте BotHost.
   Проверить автоматически переданный `PORT`. Указать реальный origin в `MINIAPP_URL`.
5. Запустить **один** процесс. Он одновременно ведёт Telegram polling и HTTP Mini App.
   Не запускать отдельный polling-контейнер ради Mini App и не разделять SQLite по двум
   независимым дискам. Модель подключения frontend+API — один origin.
6. Убедиться в логах: `Nexora 1.1.0`, сборка main.py, `Mini App HTTP listening`,
   `Telegram verified`. GET `https://ваш-домен/health` должен возвращать `up`, `1.1.0`.
   Это проверка HTTP, не доказательство ответа бота или доступности OpenRouter.
7. Открыть `/start` в личке Nexora и кнопку «Открыть Nexora». Выполнить ручные проверки ниже.

Если BotHost не предоставляет маршрут HTTPS к собственному HTTP-порту, остановиться на
подготовленной ветке. Попросить поддержку подключить домен/порт или перенести **весь один
процесс** на VPS. Статический хостинг только трёх web-файлов без API не заработает.

Источники:
https://bothost.ru/docs/domains-and-ports
https://bothost.ru/docs/manual-mini-app

## Подключение к Telegram

После готовности HTTPS, в официальном BotFather выбрать существующую Nexora:

- Bot Settings → Menu Button (или `/setmenubutton`) → HTTPS URL панели и название «Nexora».
- При необходимости Configure Mini App/Main App — тот же URL (названия пунктов зависят от клиента).
- `/start` уже формирует inline `web_app`-кнопку при корректном `MINIAPP_URL`.
- Для групп оставить согласованные права и Privacy Mode off, если нужны обращения по имени.

Проверка initData на сервере обязательна: HMAC-SHA256, сравнение в постоянное время,
срок 1 час, максимум 30 секунд расхождения часов в будущее, запрет повторяющихся полей.
Системные часы сервера должны быть корректными. Нельзя подставлять user_id в URL вместо подписи.
Полный initData не хранится, не выводится в логах и не помещается в localStorage.
По истечении часа панель просит открыть её заново из Telegram.

Источник: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app

## Миграция SQLite

Никаких DROP TABLE, очистки истории или сброса групп. При первом обновлении непустой
Nexora-базы создаётся согласованный SQLite backup `nexora.db.pre-1.1.0.bak` перед
персональной миграцией. Наличие файла препятствует его перезаписи.
Если не хватает места/прав, запуск завершается: исправить хранение до повторной попытки.
Перед обновлением также сохранить собственный backup средствами хостинга. Не копировать
только `.db`, игнорируя живой WAL; остановить Nexora либо использовать SQLite backup.
Backup приватен, его нельзя публиковать в GitHub.

Добавляется `usage.user_id` со значением 0 для старых расходов. Новые таблицы:
`profiles`, `personal_jobs`, `personal_notes`, `pro_audit`. Старые суммы остаются в общем
учёте: автор старого запроса не угадывается. Старые настройки main/background/image_model
и image_policy не стираются. Персональные основные модели теперь приоритетнее старой
групповой. Старые image_policy cap/user_cap сохранены для отката, но **не ограничивают
персональные запросы 1.1.0**; флаг разрешения изображений продолжает работать.

При первом обращении профиль Free создаётся по user ID. В старых participant preferences
ищется только однозначный предложенный ник; он не переносится автоматически в группы.
Согласие cross_chat изначально выключено. Личные заметки не заполняются автоматически
из архивов групп. Старые group memories остаются в своих chat_id.

Миграция повторяемая. После аварии pending квоты становятся uncertain до конца своего
скользящего окна; оплаченный запрос автоматически не воспроизводится.

## Временная выдача Pro без платежей

С заданным `BOT_OWNER_ID`, в **личке Nexora**, только с аккаунта владельца:

```text
/pro 123456789 24
/pro 123456789 0
```

Первая команда выдаёт доступ на 24 часа, вторая отзывает. Максимум 168 часов за выдачу.
ID — целочисленный Telegram user ID. API Mini App не имеет endpoint выдачи Pro.
Доступ Pro не меняет уважение, характер или общий денежный предел владельца.

## Ручные проверки после установки

1. `/start`, повторный `/start`, затем обычный вопрос в личке. Mini App предлагает знакомство,
   сохраняет имя, показывает реальную квоту. Повторное открытие не начинает регистрацию заново.
2. Flash в личке и группе расходует один персональный пул. Pro заблокирована на Free;
   владелец может временно выдать доступ. После отзыва запрос не должен уйти в V4 Pro.
3. Прямое имя/@/reply в группе работают; обсуждение Nexora в третьем лице и команды других
   ботов молчат. Приватная заметка из лички не появляется в групповом ответе.
4. Фото → reply «Добавь смешную шляпу, сохрани лицо и фон» → проверить изображение;
   reply на результат «Сделай фон темнее». Проверить photo и image-документ.
   На V4 Pro анализ фото использует специальную vision-модель, не молча отключается.
5. Проверить светлую/тёмную тему, iPhone/Android, клавиатуру, safe area, поворот экрана,
   переключатель моделей, прокрутку настроек, диалоги подтверждения и отсутствие бокового скролла.
6. Администратор видит только доступные группы. После снятия прав сохранить настройку
   через открытую старую панель не должно получиться. Удаление записи требует подтверждения.
7. При временном сбое API/исчерпании квоты нет повторной платной генерации и фиктивного
   успеха; причина показывается естественно, секреты в логи не попадают.

## Откат на 1.0.10

1. Остановить только Nexora 1.1.0 и убедиться, что процесс остановлен.
2. Вернуть сохранённый main.py 1.0.10/предыдущий commit. Старый бот не импортирует personal.py
   или miniapp.py. Убрать Menu Button Mini App в BotFather, если он больше не обслуживается.
3. **Не восстанавливать старую базу поверх новых оплаченных операций автоматически.**
   Добавочные поля/таблицы сохраняются, старые таблицы и настройки не переименованы.
   Старый код продолжит работать со своими полями, но пользователи снова получат прежнюю
   групповую модель и старые количественные лимиты изображений.
4. Если сама база повреждена, восстановление snapshot делать отдельно после сверки расходов
   и сохранения текущей копии: snapshot не содержит новых сообщений и оплаченных запросов.

На реальном BotHost откат и обновление этим проходом не выполнялись.
