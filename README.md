# Nexora 1.1.0 — Complete Experience (release candidate)

Обновление существующей Nexora 1.0.10. Общение остаётся в Telegram; Mini App — панель
личных настроек и доступных групп, без отдельного чата или каталога навыков.

**Рабочая версия на BotHost не изменена.** Текущий проход выполнен поверх приложенной
основы 1.1.0 в отдельной копии. GitHub и BotHost не использовались. Инструкция установки, миграции и отката: [DEPLOY.md](DEPLOY.md).

## Visual Experience & Living Mascot

Последний визуальный проход выполнен поверх полной сборки Sol. Все пять Python-модулей
сохранены побайтно: Telegram, streaming, OpenRouter, память, профили, квоты и API не менялись.

- Приглушённый фиолетовый верх переходит через серо-фиолетовый в графитовый низ.
  У светлой темы отдельная палитра, а не инверсия тёмной.
- Оригинальный белый маскот с мягким четырёхлепестковым контуром и лёгким затемнением
  краёв. SVG `d` плавно меняется между тремя совместимыми контурами за 18 секунд;
  это изменение геометрии, а не только перемещение картинки. Моргание, лёгкое парение
  и реакция на касание работают локально, без API/LLM-вызовов.
- Reduced motion останавливает морфинг и CSS-анимации; скрытая вкладка ставит их на паузу.
- Единые компактные карточки, сенсорные переключатели, видимый keyboard focus,
  safe areas с четырёх сторон, состояния ошибок и сохранения. Имя, квоты и настройки
  продолжают поступать из существующего API. Тестовые значения есть только в fixture-сервере.
- Исправлены статус ограничения Pro внутри модального окна, активная вкладка группы
  и закрытие диалога перед возвратом назад.

**Проверено:** 427 Python-тестов + 19 JavaScript-проверок; один платный live-тест пропущен.
JavaScript проверяется с DOM/API doubles, без отрисовки. Доступ к облачному браузеру
отклонён автоматической проверкой; локальный Chromium не запустился в окружении.
**Визуальная проверка, реальные iOS/Android/Telegram и плавность на устройстве остаются
ручной проверкой перед публикацией.** Чек-лист и запуск preview — в `DEPLOY.md`.

## Сохранено из прохода Sol

- Telegram metadata: автор, reply-адресат, форумная тема, пересылки и причина активации.
  Обращения к участникам, команды Iris/других ботов, игровые действия, просьбы не отвечать
  и очевидные обсуждения Nexora отсекаются локально. Неоднозначные replies проверяет
  существующий недорогой фильтр (прежние ограничения частоты сохранены).
- Настоящий OpenRouter SSE для основного ответа. В ЛС — sendMessageDraft; в группах —
  одно ожидающее сообщение и до 8 обновлений, не чаще одного раза в 4 секунды.
  Статус появляется только при заметном ожидании; typing обновляется отдельно.
  На экран попадает только JSON-поле answer, без reasoning, памяти и служебных полей.
- Остановка приватного черновика обрабатывается вне блокировки чата. Обрыв/отмена не
  запускают повторную генерацию. Неизвестная оплаченная операция сохраняет денежный
  резерв и временный quota hold; известные отклонения возвращают слот и резерв.
- Обычный JSON-ответ вместо SSE принимается одним вызовом, без имитации streaming.
  Если старый Telegram API не принимает черновики, используется обычное сообщение.
  Необязательная серверная настройка `NEXORA_STREAMING=0` отключает SSE без смены модели.
- Память выбирается по теме/участнику и актуальности, с ограничением объёма и источниками.
  Форумные темы не смешиваются в истории. Шутки, слухи, пересланные команды и чужие
  личные характеристики дополнительно фильтруются до долговременного сохранения.
  Личные заметки выбираются по теме только в ЛС; в группы они не переносятся.
- Повторное сохранение личной заметки с отличиями в пробелах/регистре не занимает новый слот.
- Новых таблиц и миграций в этом проходе нет: дополнительные Telegram metadata хранятся
  в существующем JSON. Прежняя безопасная миграция 1.0.10 → 1.1.0 сохранена.
- Эти backend-изменения сохранены в текущем архиве без дальнейших правок.

Проверки и ограничения: [TEST_REPORT.md](TEST_REPORT.md). Сетевые тесты в этой сборке —
локальные HTTP/SSE и API с тестовыми данными; реальный OpenRouter/Telegram не вызывался.

## Что реализовано

- Профили по неизменяемому Telegram user ID, автоматическое создание Free без Mini App.
- Предпочитаемое имя, стиль, отдельное согласие на использование имени/стиля между чатами.
  При однозначном старом nickname он предлагается при знакомстве, не публикуется автоматически.
- Персональная модель для обращений в личке и группах: DeepSeek V4.1 Flash по умолчанию,
  DeepSeek V4 Pro — только при действующем серверном доступе Pro. Другие пользовательские
  модели не предлагаются. Никаких платежей, подписных списаний или рекламы.
- Скользящие квоты из централизованного `personal.PLANS`, атомарные резервы SQLite,
  защита повторных updates и сообщений, сохранение после рестарта. Истечение/отзыв Pro
  переключает на Flash, проверка повторяется перед запросом к модели.
- Полноценный same-origin HTTP API + интерфейс на ES-модулях/CSS, официальный Telegram
  WebApp SDK, HMAC initData. Навигация Главная / Группы / Настройки, заметный выбор модели,
  загрузка, ошибки, отсутствие данных, подтверждения, оригинальный белый SVG-маскот с
  плавным морфингом и морганием, адаптивные стили, safe areas, тёмная/светлая тема и reduced motion.
- Личные заметки в SQLite: создание/удаление, персональная квота памяти, opt-out и удаление
  данных. В модель они передаются только в личке, не в группу даже при cross_chat=true.
- Групповые настройки и подтверждение/удаление существующих воспоминаний с актуальной
  проверкой администратора через Telegram. Старая inline-панель доступна через `/panel`.
- Существующие генерация/редактирование изображений, архив/память, web search, контекст
  reply, редкая инициатива, бюджеты и диагностика сохранены. Фоновые и системные модели
  не переключаются вместе с пользователем и скрыты из обычного выбора.

## Структура и запуск

Пять Python-файлов и три web-файла — весь runtime. Python 3.11, стандартная библиотека,
без npm-сборки, Dockerfile, PostgreSQL и новых внешних Python-зависимостей.

```sh
python3.11 -m py_compile main.py personal.py miniapp.py live.py telegram_context.py
python3.11 -m unittest discover -s tests -q
node --test tests/frontend.test.cjs  # только тестирование, Node 18+
```

Только при согласованной установке (не параллельно старому polling-процессу):

```sh
python3.11 main.py
```

Прежние BOT_TOKEN и OPENROUTER_API_KEY, новый публичный `MINIAPP_URL`, внутренний `PORT`
для HTTPS-прокси. **Один процесс, одна SQLite, один polling на токен.** Внешние запросы
должны приходить через HTTPS-прокси; мини-сервер не заменяет edge proxy/TLS.

## Тарифы и финансовая защита

| Тариф | Flash | V4 Pro | Личные записи | Персональный USD-предел в сутки |
|---|---|---|---:|---:|
| Free | 10 за 5 часов | нет | 20 | $0.20 |
| Pro | 40 за 5 часов | 25 за час | 100 | $0.50 |

Для моделей разные скользящие пулы, но один и тот же пул действует во всех чатах.
Одна составная задача — один слот, а не отдельные слоты для классификатора, текста и фото.
Ожидающие/неопределённые операции временно занимают слот; известная внутренняя ошибка
возвращает количественный слот. Суммы реально оплаченных/неопределённых операций остаются
в `usage`. Созданное изображение учитывается даже при сбое доставки Telegram.
Следующее восстановление рассчитывается из реальных времён запросов, а не фиксированного
таймера на клиента. Повтор одного update/message не производит второй платный запрос.

Сохраняются прежние финансовые дневные/месячные пределы всего бота и конкретной группы,
перезапуски их не обнуляют. Новые резервы имеют user_id и проверяются внутри той же
транзакции до платного вызова. Существующие расходы с неизвестным автором остаются в
общем учёте с user_id=0. Владелец и Pro не обходят абсолютный бюджет.

**Групповые тарифные количественные квоты изображений больше не делятся на участников.**
Старые значения сохранены в БД для отката, активен флаг разрешения изображений. Поиск
пока сохраняет прежний групповой технический потолок числа поисков как ограничение
дополнительного инструмента; личная квота запроса и финансовая защита работают поверх него.
Это не общий тарифный лимит текстового общения.

Инициатива: отдельная серверная модель, прежний антиспам, максимум 2 инициативных реплики
в сутки на группу и минимум 15 минут между ними, дополнительно $0.02 в сутки на инициативу
всего приложения. Она не расходует пользовательские тарифные слоты и не создаёт изображения.

Оценки стоимости остаются консервативными. API может вернуть иной фактический расход;
абсолютную гарантию максимального списания на стороне провайдера обеспечивает также
лимит самого OpenRouter API-ключа. Неопределённые списания не обнуляются без доказательства.
До включения платежей нужна реальная статистика стоимости и нагрузочное тестирование.

Цены snapshot без кэша/динамических маршрутов, не обещание неизменной цены. Код проверяет
доступность и ставки через актуальный каталог, а списания — по usage. Нет скрытой подмены
исчезнувшей модели. V4 Pro не получает сырые фото как текст: отдельный vision-маршрут
по умолчанию Gemini 2.5 Flash, личный выбор Pro сохраняется. Генерация и редактирование
остаются на прежней image_model. При реальном анализе фотографии надо проверить
визуальную точность на выбранном провайдере.

Фоновая Flash Lite сохранена: при 1000 входных +160 выходных токенах без кэша Flash Lite
~$0.000164, V4.1 Flash ~$0.00014172, V3.2 ~$0.0003208. Разница невелика; качество схемы,
русского языка и задержка **не замерены платным A/B**, поэтому автоматически менять
служебную модель без доказательств не стали. Владелец может задать серверный override.
Служебный маршрутизатор вызывается только для неоднозначных обращений/намерений,
память обрабатывается пакетами по существующей логике.

Источник данных: https://openrouter.ai/api/v1/models

## Приватность и доступ

- initData: проверка подписи, срока, user ID, запрет дублирующихся полей; никакого доверия
  клиентскому user_id, Telegram username или localStorage.
- Все мутации требуют авторизованного JSON-запроса, Origin проверяется при наличии;
  cookies не используются для API-аутентификации. initData — bearer-доказательство, его
  нельзя публиковать; при перехвате он действителен до истечения часа, нужен HTTPS.
- Групповые роли проверяются на сервере на каждой операции. Клиент не меняет чужие тарифы,
  модель, имя, ключи или заметки. Произвольные поля API отклоняются.
- Личные заметки — данные, не инструкции. Автоматического переноса приватной истории
  в группу нет. Согласие относится только к имени/стилю, не ко всей памяти. В группах личные тон и длина могут уточнять стиль, но юмор и мат остаются под контролем администратора.
- Прежние group memories остаются изолированы по chat_id. Массовая переоценка старого
  архива не запускается. Временная личная переписка использует прежнее окно 2 часа, архив
  по умолчанию выключен. Исторические флаги opt-out сохраняются.
- Удаление личных данных намеренно сохраняет финансовые записи, тарифный учёт и replay
  protection. Новое сохранение выключается. Оно не удаляет уже отправленное в Telegram
  или провайдеру. Политики внешних провайдеров применяются отдельно.

## Состояние проверки

Результаты и ограничения — [TEST_REPORT.md](TEST_REPORT.md). Это подготовленный выпуск
для staging-проверки владельцем, **не подтверждённый production-деплой**. Во время разработки
не было настоящих вызовов Telegram, платных completion/image/search OpenRouter и доступа
к работающей SQLite. Выполнен реальный бесплатный GET каталога. Программа и API
проверены с имитацией провайдеров и настоящей временной SQLite/локальными HTTP-сокетами.

Браузерная визуальная проверка не завершена: доступный браузер находился в другом
окружении и не видел localhost сервера (connection refused). Реальные iOS/Android WebView,
safe areas, клавиатуру, анимации и пиксельную точность надо проверить вручную до установки
для всех. SVG-маскот оригинальный программный; отдельная художественная доработка возможна.
